# タイムラインの行移動と当たり判定の改修

- 日付: 2026-07-30
- 対象: `mosaic_tool/video/session.py`, `mosaic_tool/video/lanes.py`, `mosaic_tool/video/timeline_window.py`, `mosaic_tool/app.py`

## 背景

タイムラインの区間バーは現在、平行移動（開始・終了フレームの変更）しかできない。
行（レーン）は `lanes.build_rows` が毎回 `pack_lanes` で自動計算しており、
区間自身は行の情報を持たない。そのため次の不便がある。

- 見やすい位置へ行を並べ替えられない
- 横に並んだバーの端が近接すると、選択中のバーではない方をつかんでしまう
- バーをクリックしただけで再生位置が飛ぶ（意図せず表示フレームが変わる）

## 要件

1. 区間バーを縦にドラッグして、同じカテゴリ（ペン / 矩形 / 自動検出）の行へ移動できる
2. 区間が時間的に被った場合は自動で行を変える。ただし手動で入れ替えた行を優先する
3. 横並びしているバーの当たり判定は、選択中の区間を優先する
4. 区間を選択したときの自動シークを無効化する

## 決定事項

| 論点 | 決定 |
| --- | --- |
| 縦移動の範囲 | 同カテゴリの既存行 + 末尾に 1 行（新規行の追加）。カテゴリはまたげない |
| 手動指定同士の衝突 | 新しい操作を優先し、押し出された側は手動指定を失って自動配置へ戻る |
| 手動指定とみなす契機 | ドラッグ終了時の行を常に固定（横移動・リサイズを含む） |
| 複数選択の縦移動 | 全員を同じ行数だけずらす。誰か一人でもカテゴリ外へ出る分は全体をそこで止める |

## 設計

### 1. データモデル

`VideoRegion` に手動レーンを持たせる。

```python
@dataclass
class VideoRegion:
    region: Region
    start: int
    end: int
    source: RegionSource | None = None
    # タイムラインの行(カテゴリ内のレーン番号)。None は自動配置
    lane: int | None = None
```

動画セッションはメモリ上のみで、区間の永続化形式は存在しない。
よって保存・読み込みへの影響はない。

### 2. 行構成（`lanes.py`）

`build_rows` はカテゴリごとに独立して次の順で配置する。

1. `lane` を持つ区間を、指定レーンへ先に置く
2. 手動同士が同レーン・同時刻で被っていたら、`regions` の並びで後ろにある方の
   `lane` を `None` に落として自動扱いにする（防御的措置。通常はドラッグ確定
   時に解消済みで、ここへは来ない）
3. `lane is None` の区間を開始フレーム順に、手動の占有を避けながら最上段の
   空きレーンへ詰める

空き判定はレーンごとの占有区間ソート済みリストへの二分探索で行う。
自動検出がフレームごとの区間で数千個並んでも `O(n log m)` に収まる。

**空レーンも行として返す。** 手動で lane 2 に置き lane 0/1 が空になる状態でも、
レーン番号と表示行を一致させる必要がある。`items` が空の `TimelineLane` を返す。
カテゴリラベルは先頭行にだけ描くため、見た目の変化は空行が挟まることだけ。

### 3. レーン移動量のクランプ（`lanes.py`）

横移動の `clamp_delta` と対になる純ロジックを置く。

- 選択中の各区間について、カテゴリ内の現在レーン index に同じ delta を足す
- 誰か一人でも `[0, そのカテゴリのレーン数]` を外れる分は全体をそこで止める
  （上限がレーン数そのものなのは、末尾 +1 が新規行になるため）
- 個別クランプにしない。選択内の上下関係が崩れて並びが意図せず潰れる

### 4. 縦ドラッグ（`timeline_window.py`）

- `TimelineArea` は `set_data` で受けた `regions` を保持する。ドラッグ中に
  自前で `build_rows` を回し直して行の変化を即座に描くため
- MOVE ドラッグ中は x に加えて y も追い、つかんだ行と anchor の行の差から
  目標レーンを出す。上のクランプを通してから選択全員の `lane` を書き換え、
  行を再構成して再描画する
- ドラッグ確定（`mouseReleaseEvent`）では MOVE / START / END のいずれでも、
  `_drag_items` 全員の `lane` をその時点の行へ固定する
- 固定した区間と同カテゴリ・同レーンで時間が被る他区間は `lane` を `None` へ
  戻す。あとは `build_rows` の再構成で自動的に別レーンへ流れる

### 5. 当たり判定の選択優先（`timeline_window.py`）

`_bar_at` と `_edge_at` の走査順を「選択中のバー → 非選択のバー」の 2 周に
変える。各周の中では従来通り後に描いたものを優先する。
横に並んだバーの端が `HANDLE_PX` の範囲で競合しても、選択中の端が勝つ。

### 6. 自動シークの無効化

- `TimelineArea.region_clicked` / `TimelineWindow.region_clicked` シグナルと
  `app._on_timeline_region_clicked` を削除する
- バークリック時のキャンバス選択は既存の `selection_changed` 経由で伝わるため、
  シークを外すと `region_clicked` の役割は完全に重複する
- ルーラーのクリック / ドラッグによるシークは従来通り残す

## テスト

`tests/test_video_lanes.py`

- 手動レーンが尊重される
- 手動同士が被ったら後から来た方が自動配置へ落ちる
- 自動区間が手動の占有を避けて詰まる
- 手動レーンより上が空くと空の行が返る
- レーン移動量のクランプ（上下端、複数選択、新規行の +1）

`tests/test_video_timeline_window.py`

- 縦ドラッグで `lane` が付き、行が変わる
- 横ドラッグ・リサイズの終了時にも `lane` が固定される
- 縦ドラッグで被った他区間の `lane` が `None` に戻る
- 当たり判定が選択中の区間を優先する（バー本体・端の両方）
- バークリックで `seek_requested` が出ない
- ルーラーのクリックでは従来通り `seek_requested` が出る

既存テストのうち `region_clicked` を検証しているものは削除する。

## 非対象

- カテゴリをまたぐ行移動（`source` の変更）
- 行の並び順そのものの永続化
- 行の高さやカテゴリ順のカスタマイズ
