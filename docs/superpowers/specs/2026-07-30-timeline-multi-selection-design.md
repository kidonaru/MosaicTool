# タイムラインの選択と区間編集の改修

## 背景

動画モードのタイムラインウィンドウ（`mosaic_tool/video/timeline_window.py`）には
すでに「選択バーの色替え」と「端ドラッグによる区間のリサイズ」がある。しかし
実際には選択の強調が見えず、区間編集も扱いにくい状態にある。

原因は選択状態をキャンバスから借りていることにある。タイムラインのバーを
クリックすると app はシークを通し、約 200ms 後に settle タイマーが原寸フレームを
描き直す。このとき `canvas.set_image()` がシーンを作り直すため（`app.py:855`）、
直前に付けた選択が消える。さらに続く `canvas.setFocus()`（`app.py:856`）が
タイムラインウィンドウからフォーカスを奪うため、Delete と Space も効かなくなる。

キャンバスは表示中フレームに掛かる範囲しか持たないため、この作りのままでは
複数区間の選択も実現できない。自動検出はフレームごとの独立区間を数千個作るので、
まとめて選んで消す・まとめてずらす操作が求められる。

## 目的

1. 各区間バーの開始/終了の境目を線で見えるようにする
2. 選択中の区間を確実に強調表示する
3. タイムライン上の矩形選択で複数の区間を選べるようにする
4. 選択した区間を伸び縮みさせられるようにする（複数選択時は一括）

## 方針

選択状態の持ち主をキャンバスからタイムラインへ移す。タイムラインが自分の選択集合を
唯一の真として持ち、キャンバスへはベストエフォートで反映する。これにより
フレーム切替やシーンの作り直しで選択が消えなくなり、現在フレームに掛かっていない
自動検出の区間も選択できる。

選択集合と一括編集のクランプ計算は Qt ウィジェットから切り離した純ロジックとして
新モジュールへ置く。クランプの仕様は細かく（選択のうち 1 つでも範囲外に出たら
全体を止める、など）、`mousePressEvent` の中に埋めると挙動を確かめられない。
既存の `video/lanes.py` と同じく、純ロジックを別モジュールへ出してウィジェット
無しでテストする形に揃える。

## モジュール構成

### 新規: `mosaic_tool/video/timeline_selection.py`

Qt ウィジェットに依存しない。

`TimelineSelection` — 選択中 `VideoRegion` の集合。同一インスタンス比較で、
挿入順を保持する。

| メソッド | 役割 |
|---|---|
| `items()` | 選択中の `VideoRegion` を挿入順で返す |
| `contains(vr)` | 含まれるか（同一インスタンス比較） |
| `replace(items)` | 選択を差し替える |
| `toggle(vr)` | 含まれていれば外し、無ければ加える |
| `add(items)` | 加算する（重複は無視） |
| `clear()` | 空にする |
| `prune(regions)` | セッションから消えた区間を選択から落とす |

一括編集は「共通デルタを求めて全員に適用する」2 つの純関数で表す。
`kind` は `"start" | "end" | "move"`。

- `clamp_delta(items, kind, delta, max_frame) -> int`
- `apply_delta(items, kind, delta) -> None`

クランプ規則:

| kind | 全選択が満たすべき条件 |
|---|---|
| `move` | `0 <= start + d` かつ `end + d <= max_frame` |
| `start` | `0 <= start + d <= end` |
| `end` | `start <= end + d <= max_frame` |

選択のうち 1 つでも端に当たった時点で全体が止まる。選択内の相対位置を崩さない
ためで、個別にクランプすると区間の並びが意図せず詰まる。

### 変更: `mosaic_tool/video/timeline_window.py`

描画・ヒット判定・イベント振り分けに専念する。選択集合は `TimelineSelection` に、
一括編集のクランプは上記の純関数に委譲する。

## 選択の所有とデータフロー

`TimelineArea` が選択の唯一の真とする。キャンバス選択には依存しない。

- `TimelineWindow.set_data(regions)` — `selected` 引数を削除し、内部で `prune` する
- **タイムライン → キャンバス**: `selection_changed = Signal(list)` を追加。app は
  現在フレームに掛かる分だけを抜き出して `canvas.select_regions()` へ流す
- **キャンバス → タイムライン**: 既存の `canvas.selection_changed` の中継は維持するが、
  **選択が空でないときだけ**タイムラインへ反映する。シーン再構築で起きる選択消失は
  常に空になるため、これで巻き込まれない。加えて app に再入ガードフラグを置き、
  自分が流した同期で往復しないようにする
- `canvas.setFocus()`（`app.py:856`）は**メインウィンドウがアクティブなときだけ**
  呼ぶ。タイムラインウィンドウ操作中のフォーカス奪取を止める

キャンバスから空の選択を無視する副作用として「キャンバスの空白をクリックして
選択解除」がタイムラインへ伝わらなくなる。タイムラインの空白クリックで解除できる
ため許容する。

## 入力操作

| 押下位置 | 修飾 | 動作 |
|---|---|---|
| ルーラー | — | シーク（変更なし） |
| バーの端（±`HANDLE_PX`、全バー対象） | — | 選択に含まれる→選択全体を一括リサイズ／含まれない→単体選択してリサイズ |
| バー本体 | — | 選択済み→選択全体を一括平行移動／未選択→単体選択して移動＋クリック位置へシーク |
| バー本体 | Ctrl / Shift | 選択のトグル（ドラッグ移動はしない） |
| 空白 | — | 矩形選択開始（既存選択をクリア） |
| 空白 | Ctrl / Shift | 矩形選択開始（既存選択へ加算） |

- 矩形と**交差**するバーを選択する。完全内包は要求しない。行とカテゴリを跨げる
- 「空白」はルーラーより下のすべてを指す。行と行の隙間や最下段より下から始めても
  矩形選択になる
- `setMouseTracking(True)` を有効化し、端付近で `SizeHorCursor`、
  バー上で `OpenHandCursor` に変える
- Delete / Backspace で選択中すべてを削除する。`delete_requested` を
  `Signal(list)` へ変更する
- Space は変更なし

端ハンドルを全バーで掴めるようにするため、既存の `_edge_at` から
「選択中のバーに限る」条件を外す。短いバーで判定幅を細める既存の調整
（`min(HANDLE_PX, bar.width() / 3)`）は残し、密集時に中央を掴む余地を保つ。

## 描画

- **バー端の縁取り線**: 全バーの左右端 1px を明るい色で描く。バー幅が 3px 未満なら
  省略して潰れを防ぐ
- **選択の強調**: 選択中は `_SELECTED_COLOR` に白 1px のアウトラインを重ね、端の
  縁取りは白 2px にする。**選択が 1 つ以上あるときだけ**非選択バーを沈んだ色で描く。
  選択が空なら従来の `_BAR_COLOR` のまま
- 既存の「選択バーの端に白 3px」は縁取り線へ統合し、二重描画をやめる
- 矩形選択中は半透明の塗りと点線枠を、区間バーより前・ラベル列より後に描く

## app.py 側の変更

- `interval_edited(Region, int, int)` を `intervals_edited()`（引数なし）へ簡素化する。
  `TimelineArea` は既に `VideoRegion` を直接書き換えており、受け側は同じ値を
  代入し直すだけで実質 no-op になっている。一括編集で対象が複数になるため
  「区間が変わった」通知へ寄せる
- `intervals_edited` の受け口で `_dirty = True` に加え、
  `canvas.set_playback_regions(video.regions_at(frame))` を呼ぶ。区間を動かして
  現在フレームの掛かり具合が変わったことを即座に反映する。掛かる範囲の集合が
  変わったときだけ作り直す実装なので安価
- `_on_timeline_delete` を複数対応にする（`canvas.delete_regions` は既に複数対応）
- `_update_timeline_window` はキャンバス選択を読まなくなり、区間リストだけを渡す

## テスト

**新規** `tests/test_video_timeline_selection.py`

- 集合操作（`replace` / `toggle` / `add` / `clear` / `contains` の同一インスタンス比較）
- `prune` がセッションから消えた区間だけを落とす
- `clamp_delta` の境界: 0 未満へ寄せた移動、末尾超えの移動、`start` が `end` を
  越える縮小、`end` が `start` を下回る縮小
- 複数選択で 1 つだけが端に当たるとき、全体がその分で止まる

**追記** `tests/test_video_timeline_window.py`

- 矩形選択が交差するバーを選び、行とカテゴリを跨ぐ
- Ctrl+クリックが選択をトグルし、ドラッグ移動を始めない
- 未選択バーの端を掴んでリサイズできる
- Delete が選択中すべてを載せた `delete_requested` を 1 回出す
- `set_data` 後に消えた区間が選択から落ちる

**追記** `tests/test_app.py`

- タイムライン選択がキャンバスへ現在フレームの分だけ流れる
- キャンバス選択が空のときタイムライン選択を消さない
- 選択同期が往復しない

## スコープ外

`canvas.set_image` が毎シークで Undo スタックを消している点（`canvas.py:485`）は
別の問題として扱い、本改修では触らない。
