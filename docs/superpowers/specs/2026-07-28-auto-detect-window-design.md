# 自動検出ウィンドウ 設計

前提: `2026-07-28-auto-detect-design.md` で構築した自動検出機能への追加設計。

## 目的

自動検出の操作をツールバーから独立したウィンドウへ移し、次の 3 点を解決する。

1. **モデル単位の制御ができない** — 全モデルを一律の信頼度で必ず走らせるため、不要なモデルを外せず、モデルごとに最適値が違う信頼度も妥協値しか置けない(実測値は `docs/detection-models.md` を参照)
2. **モデルの入手が手作業** — ユーザーが自力で `.pt` を探して `models\` へ置く必要がある
3. **検出の進行が見えない** — 実行中はステータスバーの「検出中...」だけで、何秒かかるのか分からない

あわせて、検出後に追加分が選択状態になる挙動をやめる。手直しの起点として選択されていることより、意図せず全体を動かしてしまう事故のほうが多い。

## 方針

### ウィンドウはモードレス

検出 → 結果を見る → 信頼度を下げる → 再検出、という往復が主な使い方になる。モーダルだと毎回閉じ直すことになるため、開いたままメインウィンドウを操作できるモードレスウィンドウ(`QDialog` + `setModal(False)`)とする。画像を次へ進めながら連続で検出することもできる。

### セットアップは既存ダイアログを流用する

`RuntimeSetupDialog` は venv 構築に閉じた責務を持っており、そのまま使える。検出ウィンドウ側は「推論環境: 未構築 / 構築済み」の表示と `[セットアップ]` / `[再セットアップ]` ボタンだけを持ち、未構築の間はモデル欄と検出ボタンを無効化する。

ウィンドウ自体を状態別ページに分けるより差分が小さく、「セットアップ済みでも再セットアップできる」という要件がそのまま満たせる。

### 標準モデルはセットアップ時に自動ダウンロードする

一覧から個別に DL させるのではなく、セットアップの一部として 3 件をまとめて取得する。いずれも 6MB 前後で venv 構築(250MB〜2.5GB)に比べれば無視できるコストであり、「セットアップしたら使える状態になっている」ほうが導線として短い。

そのため検出ウィンドウには標準モデル一覧を置かず、`models\` の実ファイル一覧だけを表示する。

## モジュール構成

`app.py`(497 行) と `canvas.py`(850 行) はすでに大きいため、新規 UI は `mosaic_tool/detect/` 配下に分割して置く。

| ファイル | 責務 |
|---|---|
| `detect/catalog.py` (新規) | 標準モデルの定義(ファイル名・用途名・サイズ・URL・推奨 conf)。GUI 非依存の定数のみ |
| `detect/downloader.py` (新規) | `QNetworkAccessManager` による 1 ファイルのダウンロード。進捗・完了・失敗をシグナルで通知 |
| `detect/detect_window.py` (新規) | 自動検出ウィンドウ本体 |
| `detect/setup_dialog.py` | 既定選択を常に CPU へ変更。venv 構築後に標準モデルの取得を続ける |
| `detect/worker_main.py` | リクエストで指定されたモデルだけ推論。モデル 1 件ごとに進捗を出力 |
| `detect/convert.py` | リクエストにモデル別 conf を載せる。応答の種別(ready / progress / detections)を判別する |
| `detect/worker_client.py` | `progress` シグナルを追加。モデル構成が変わったときの再起動 |
| `settings.py` | モデル別の有効/無効と信頼度を追加。全体の信頼度設定を削除 |
| `app.py` | ツールバーの信頼度スピンボックスを削除し、ボタンでウィンドウを開く |
| `canvas.py` | `add_regions()` の自動選択をやめる |

## 標準モデルカタログ

`docs/detection-models.md` の検証結果に基づき、HuggingFace から認証なしで直接取得できる Anzhc のセグメンテーションモデル 3 件を定義する。

| ファイル名 | 用途 | サイズ | 推奨 conf |
|---|---|---|---|
| `Anzhc Face seg 640 v4 y11n.pt` | 顔 | 5.7MB | 25% |
| `Anzhc Eyes -seg-hd.pt` | 目 | 6.6MB | 40% |
| `Anzhc HeadHair seg y8n.pt` | 髪 | 6.5MB | 25% |

すべて [Anzhc/Anzhcs_YOLOs](https://huggingface.co/Anzhc/Anzhcs_YOLOs) (AGPL-3.0)。URL は
`https://huggingface.co/Anzhc/Anzhcs_YOLOs/resolve/main/<URL エンコードしたファイル名>` の形式で、
CDN へ 302 リダイレクトするためリダイレクト追従が必須。

髪は `y8n`(6.5MB)を採用する。`y8m` は 52MB あり、他 2 件とサイズ感が揃わない。髪の推奨 conf は
実測していないため既定値の 25% を置く。

推奨 conf は「そのモデルが初めて `models\` に現れたときの初期値」としてのみ使い、以後はユーザーの設定が優先される。カタログに無いモデルの初期値は既存の `DEFAULT_CONFIDENCE = 25`。

用途名(顔 / 目 / 髪)はモデル一覧の表示にも使う。カタログに無いモデルは用途名を空欄にする。

### カタログに載せないモデル

`docs/detection-models.md` で検証した以下は、認証が必要か、アプリ内に一覧として掲示するのが適切でないため自動ダウンロードの対象にしない。README の「その他の検出モデル」節に入手先・推奨 conf・`models\` へ手動で置く手順を記載する。

- `cockAndBallDetection2D_v20.pt` — Civitai (要ログイン) / 推奨 20%
- `nsfw-seg-vagina-s.pt` — NSFW-API (HuggingFace) / 推奨 15%
- `Anzhc Breasts Seg v1 1024s.pt` — Anzhc (HuggingFace)

手動で置いたモデルも `[更新]` を押せば一覧に現れ、チェックと信頼度の設定対象になる。

## ウィンドウのレイアウト

```
自動検出                                              [モードレス]
─────────────────────────────────────────
推論環境: 構築済み                          [ 再セットアップ ]
─────────────────────────────────────────
モデル                                  [ フォルダを開く ][ 更新 ]
 ☑ Anzhc Face seg 640 v4 y11n.pt  顔  ───●──────  25 %
 ☑ Anzhc Eyes -seg-hd.pt          目  ──────●───  40 %
 ☑ Anzhc HeadHair seg y8n.pt      髪  ───●──────  25 %
 ☐ cockAndBallDetection2D_v20.pt      ──●───────  20 %
─────────────────────────────────────────
[███████████░░░░░░░]  2/4 Anzhc Eyes -seg-hd.pt
                                      [ 検出実行 ]  [ 閉じる ]
```

- モデル一覧は `models\` 直下の `.pt` をファイル名順に並べる。行の構成は「チェックボックス / ファイル名 / 用途名 / 信頼度スライダー(1〜100%) / 現在値ラベル」
- チェックが外れている行はスライダーと値ラベルを無効化する
- `[フォルダを開く]` は `models\` を作成してからエクスプローラで開く(既存 `_warn_models_missing()` と同じ処理)
- `[更新]` は一覧を再スキャンする。手動でモデルを追加・削除したときに使う
- プログレスバーは検出中だけ表示する。待機中は非表示(セットアップ中の進捗は `RuntimeSetupDialog` 側に出る)
- 未構築時: モデル一覧・`[検出実行]` を無効化し、環境の行に「未構築」と `[セットアップ]` を出す
- 有効なモデルが 0 件、またはメインウィンドウに画像が無いとき: `[検出実行]` を無効化する

ウィンドウは 1 つだけ持ち、2 回目以降は `raise_()` / `activateWindow()` で前面に出す。メインウィンドウの終了時に一緒に閉じる。

## セットアップの流れ

`RuntimeSetupDialog` を次のように変更する。

1. GPU / CPU の選択。**既定は常に CPU**(現在の `has_nvidia_gpu()` による自動選択をやめる)。GPU は明示的に選んだときだけ使う
2. `[開始]` → 既存どおり venv を構築
3. 続けて標準モデル 3 件を順にダウンロードする。`models\` に同名ファイルが既にあればスキップする
4. すべて終わったら `accept()`

ダウンロード中はログ欄に「モデルを取得中: <名前> (2/3)」を出し、プログレスバーを進める。

ダウンロードが失敗しても venv 構築が成功していればセットアップは**成功扱い**とし、ログに警告を残すだけにする。venv さえあれば手動でモデルを置いて使えるため、ここで全体を失敗にすると復旧手段まで塞いでしまう。取得できなかったモデルは次回の再セットアップで再試行される。

`has_nvidia_gpu()` は既定の出し分けに使わなくなるが、GPU 選択肢のラベルに「NVIDIA GPU を検出しました」といった補足を出す用途で残す。

## ワーカープロトコルの変更

### リクエスト

```jsonc
{"image": "C:\\...\\a.png", "device": "", "models": {"Anzhc Face seg 640 v4 y11n.pt": 0.25, "Anzhc Eyes -seg-hd.pt": 0.4}}
```

`models` はファイル名をキー、信頼度(0〜1)を値とする辞書。ここに載っていないモデルは推論しない。既存の全体 `conf` フィールドは削除する。

### 応答

```jsonc
{"ok": true, "ready": true}                                    // 起動直後に 1 回
{"ok": true, "progress": {"done": 1, "total": 2, "model": "..."}}  // モデル 1 件ごと
{"ok": true, "detections": [...]}                              // 最後に 1 回
{"ok": false, "error": "..."}                                  // 失敗時
```

進捗はモデルの推論が終わるたびに出す。`total` は `models` の件数。

### ロードと再起動

ワーカーは起動時に `models\` の `.pt` を**全件**ロードする。チェックの切り替えでは再起動しない(ロードには数秒かかるため、切り替えのたびに待たされるのは避ける)。

一方、`models\` の顔ぶれが変わったとき — セットアップでのダウンロード完了時と `[更新]` 押下時 — はワーカーを `stop()` し、次のリクエストで新しい構成のまま起動し直す。

### 実装への影響

- `convert.py`: `build_request()` の引数を `models: dict[str, float]` に変更。`parse_response()` は検出リストを返す関数から、応答の種別を判別して返す関数へ変更する(`ready` / `progress` / `detections`)。`DetectError` の扱いは変えない
- `worker_client.py`: `progress = Signal(int, int, str)` を追加。現在は「起動直後の 1 行目を ready とみなす」という位置ベースの判定をしているが、応答に種別が入るためフラグ(`self._ready`)ではなくペイロードを見て分岐する
- `worker_main.py`: `detect()` にモデル別 conf と進捗コールバックを渡す。`models` に無いモデルは飛ばす

## 設定の永続化

`AppSettings` にモデル別の設定を追加する。キーはファイル名。

| キー | 既定値 |
|---|---|
| `detect/models/<ファイル名>/enabled` | `True` |
| `detect/models/<ファイル名>/confidence` | カタログの推奨値。カタログに無ければ 25 |

未登録のモデルは「有効・推奨 conf」として扱う。ユーザーが `models\` に置いたものは使いたくて置いたはずで、初期状態で無効だと「置いたのに動かない」という戸惑いを生む。

既存の全体設定 `detect/confidence`(`DEFAULT_CONFIDENCE`)は使われなくなるため削除する。`detect/device` は据え置き(現状 UI からは設定できないが、`AppSettings.device()` は検出リクエストで参照されている)。

QSettings のキーにファイル名を含めるため、`/` を含むファイル名は階層として解釈される。`.pt` のファイル名に `/` は入り得ないが、`\` や特殊文字を含む名前でも壊れないよう、キーにする際は `QSettings.beginGroup()` を使わず単一キー文字列として組み立てる。

## 検出の実行

1. `[検出実行]` 押下 → 有効なモデルとその信頼度を集める
2. `[検出実行]` を無効化し、プログレスバーを 0/N で表示
3. `DetectWorker.request()` に画像パス・デバイス・モデル辞書を渡す
4. `progress` シグナルでバーを進める
5. `detected` シグナルで範囲を追加し、バーを隠して `[検出実行]` を戻す

結果の反映(範囲の追加、ステータスバーのメッセージ)は現行どおりメインウィンドウ側で行う。ウィンドウは検出の指示と進捗表示だけを担い、`MainWindow` の `_on_detected()` / `_on_detect_failed()` はそのまま使う。

### 追加後の選択解除

`canvas.add_regions()` から `item.setSelected(True)` を外す。追加分は非選択のまま置かれる。

ペン・矩形で手描きした直後の選択(`add_region().setSelected(True)`)はそのまま残す。描いた直後にサイズを調整したいのは自然な流れであり、こちらは変えない。

## エラー処理

| 状況 | 挙動 |
|---|---|
| モデルのダウンロード失敗(通信エラー / HTTP 4xx,5xx) | `.part` を削除し、ログに警告。セットアップは続行 |
| ダウンロード中のキャンセル | `QNetworkReply.abort()` → `.part` を削除 |
| 有効モデルが 0 件 | `[検出実行]` を無効化(押せない) |
| ワーカーの異常終了 / タイムアウト | 現行どおり。プログレスバーを隠して `[検出実行]` を戻す |

ダウンロードは `<ファイル名>.part` へ書き、完了時に `rename()` する。中断したファイルが `.pt` として一覧に現れ、ロード時に壊れたモデルとして失敗するのを防ぐ。

## テスト

既存方針に合わせ、GUI に依存しない部分をユニットテストする。ウィンドウ本体と `downloader.py` は手動確認とする。

- `catalog.py`: ファイル名の重複が無いこと、URL がリポジトリの形式に沿うこと、推奨 conf が 1〜100 の範囲にあること
- `convert.py`: `build_request()` がモデル別 conf を載せること。`parse_response()` が ready / progress / detections / エラーを判別すること
- `worker_main.py`: `handle_request()` が `models` に載ったモデルだけを呼ぶこと、モデルごとに異なる conf を渡すこと、進捗が件数分出ること(`YOLO` はスタブに差し替え)
- `settings.py`: モデル別設定の既定値・保存・不正値の丸め
- `canvas.py`: `add_regions()` の追加分が非選択であること

`uv.exe` 以外に新しい同梱物は増えない。README に次を追記する。

- セットアップ時に標準モデルが自動ダウンロードされること

## スコープ外

- フォルダ内画像の一括自動検出
- モデルの削除・リネームなどのファイル操作(`[フォルダを開く]` で代替)
- Civitai API キーによる認証ダウンロード
- 検出元モデルを `Region` に持たせて UI で識別できるようにすること
- ダウンロードの再開(レジューム)
